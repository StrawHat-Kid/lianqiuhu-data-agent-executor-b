# HC 纯问数知识库转换说明（v3）

## 正式生产结构

执行器 `knowedge/` 顶层只保留以下四个生产知识文件：

1. `00_回答规则.md`
2. `01_权威指标事实表.csv`（696 条事实）
3. `02_事件告警表.csv`（35 条事件）
4. `03_指标词典与口径.csv`（315 条指标词典）

执行器会扫描 `knowedge/` 顶层的全部普通文件，并按文件名排序后全文注入本轮模型上下文。因此不要保留旧版 7 个生产知识文件、ZIP 原包、验证文件或子目录，以避免新旧数据同时注入造成污染。

`validation/` 仅用于离线校验，不属于正式模型知识库，不能移动到 `knowedge/`。

## 数据与口径校验

事实表已完成前置检查：696 条事实无完整重复，且相同业务键下不存在 `value` 或 `unit` 冲突。指标词典与事实结构匹配。

设施管理以下三组数据的 01～31 已按方案确认解释为本月第 1～31 日：

- 设施工单 / 工单数量
- 设施告警 / 告警数
- 设施运行 / 时长

三组共 93 条事实，`time_type` 为“月内日序列”，`time_index` 为 1～31，词典 `time_rule` 为“系统时间月份内按日展示。”它们不是小时序列，不能把 `02:00:00` 映射为本月第 2 日。

## 回答规则与 Prompt

正式业务回答规则以 `00_回答规则.md` 为准。它要求先按用户明确的专题硬筛选，再匹配组件、指标、分类条件和时间；唯一结果直接回答，无法唯一匹配时只提出一个简短澄清问题，不罗列候选。

默认不主动添加“以下基于模拟演示数据”等声明。只有用户明确询问真实性、模拟性、来源或可信性时，才说明数据根据真实系统的模拟数据生成，供演示使用。

核心 Python 无需因本次知识库升级修改。`config.json` 与 `config.example.json` 的 `system_prompt` 应只强调严格遵守 `00_回答规则.md`、依据事实作答、保持数值与时间口径，以及避免内部字段、文件名和检索过程；不要再复制一套与知识库冲突的业务规则。

## 验收建议

先执行机械校验：四文件结构、事实/事件/词典数量、重复与冲突、三组月内日序列及对应词典时间规则。随后通过 `/api/chat` 和不带 callback 的 `/api/commands` 进行真实模型验收，覆盖固定指标、专题硬条件、单位、月内日序列、月累计、事件、模糊澄清、真实性询问与相对日期。
